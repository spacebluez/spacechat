# 多房间、加密存储与多行输入

用户已确认：任意非空口令创建房间，同口令进入同房间；Enter 发送，Shift+Enter 换行；每天北京时间 00:00 清理全部房间，在线用户继续发送可重新建房；独立部署，不停止或重启旧服务。

## 边界
- 基于现有功能分支建立 codex/multi-room-encryption，保留旧服务及旧数据，不迁移历史。
- 口令精确匹配，1–256 字符，不得全为空白或含控制字符。不提供房间枚举或管理员建房。
- 在线昵称、历史、实时广播、分页和断线补齐均在房间内隔离。
- 数据库仅保存 HMAC 派生的房间标识；昵称与正文使用 AES-256-GCM 加密。随机 nonce，房间、消息编号、时间戳作为认证附加数据。
- 独立随机主密钥位于受限配置文件；派生独立的加密和房间标识密钥。启动验证密钥，错误密钥或旧明文数据库拒绝启动。不提供本期密钥轮换。
- 数据库元数据、时间、消息数量不加密。服务端能解密；非端到端加密，ws 链路仍需可信内网或外部 TLS。
- 逻辑清理删除全部消息和房间、更新同步代次，通知在线用户清空历史但保留草稿。保留连接的房间标识用于下次发送重建，不保留历史。
- 定时及手动 Python 脚本均通过新服务独有 Unix socket 清理，不能默认访问旧实例。
- 新实例使用 xchat-rooms 服务名，独立配置/数据/运行目录，默认示例端口 18081。不在仓库写真实地址或密钥。

## 实现
保留单房间兼容接口用于回归测试；新启动入口强制使用加密存储及房间模式。会话持有受限的房间仓储，不能在请求中切换房间。全量清理与发送共享服务锁，数据库事务保证一致性。

输入改为多行编辑器，限制 2000 字符。正文允许 LF，昵称仍禁止控制字符。Windows 从原生按键事件读取 Shift 修饰键，转换为明确的换行消息；不依赖发送时查询键盘状态。粘贴多行不自动发送。提供 Ctrl+J 兼容换行。

## 验收
加密明文扫描、错误密钥与篡改拒绝、持久化与分页；跨房间重名/消息/用户列表/同步隔离；全部清理后在线续聊；多行输入与 Windows 伪终端；完整测试、Linux race、独立服务健康和旧进程启动时间不变。
