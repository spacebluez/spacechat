# 共享密钥与每日清理设计

状态：用户已确认；开发分支 codex/access-key-daily-cleanup。

## 需求

1. 进入时输入昵称和共享密钥。服务端读取受限权限的密钥文件，本次生产密钥由部署时配置，不进入源码、构建包、日志或 Git。
2. 提供清理脚本和可配置的 systemd timer，默认每天北京时间 00:00 清空全部历史。
3. 完成后部署 dev216、打包 Windows 客户端并推送开发分支，不合并 main。

## 密钥验证

join 协议新增 access_key。服务端先验证密钥，再读取在线列表、历史或占用昵称；错误与缺失密钥均返回 unauthorized。密钥文件默认部署到 /etc/xchat/access.key，root:xchat、0640；启动未配置或为空时失败关闭，不允许退化为匿名服务。通过固定长度摘要的常量时间比较校验。

客户端登录页提供昵称和掩码密钥两项，Tab 切换，Enter 从昵称进入密钥项或提交。密钥仅留在本进程内存，断线重连复用；服务器拒绝密钥时停止重连并回到输入页。更新密钥文件后重启服务使配置生效。旧客户端无密钥，不能进入新版服务端。

共享密钥不是用户身份认证。ws 仍为内网明文，不能抵抗链路窃听；生产密钥不写在本文档。

## 在线清理

SQLite 事务中 DELETE 全部 messages 并更新聊天室实例 ID，保留递增序列、schema 和数据库文件。提交失败不改变实例或客户端状态。

聊天服务使用已有事件锁串行化发送、同步和清理。事务成功后丢弃未发出的旧同步缓存，向每个连接按序发送 history_cleared（新实例 ID、清理时间、删除数量）；新发送的消息排在事件之后。正在同步的连接转为实时状态，滞后的旧 sync 请求忽略。客户端收到事件后清空历史视图、分页状态和旧发送提示，保留昵称、密钥、输入草稿及在线连接；重置同步游标。离线客户端重连发现实例变化后重新加载，不复活旧记录。

## 管理接口与定时器

仅通过 /run/xchat/admin.sock 的 Unix socket 提供 POST /clear-history，socket 为 0600，owner 为 xchat；普通聊天连接和公共 HTTP 不提供清理入口。管理接口返回已删除条数，失败返回非 2xx。

cleanup.sh 通过 curl --unix-socket 调用并检查 HTTP 状态。systemd oneshot 单元以 xchat 用户调用脚本；timer 配置 OnCalendar=*-*-* 00:00:00 Asia/Shanghai，AccuracySec=1s，RandomizedDelaySec=0，Persistent=false。不补跑停机期间的午夜任务，以免启动后意外删除新消息；错过时等待下个计划时间。管理员可用 timer drop-in 修改时间，重载并重启 timer。清理脚本失败会让 oneshot 失败并保留日志。

## 验收

- 未提供/错误密钥只返回错误，不返回用户或历史；正确密钥收发和重连正常。
- 密钥掩码显示，配置和程序不包含生产密钥。
- 清空后数据库为零条、实例变化、ID 不回退，重启后仍有效；事务失败不清除部分数据。
- 在线、离线以及同步中的客户端不恢复旧消息，清理后能继续发送。
- 公共 HTTP 无管理接口；socket 权限正确，失败请求可检测。
- 配置显示下一次北京时间 00:00；在隔离实例进行短时间 timer 真实触发验证，不依赖等待午夜。
