# 客户端房间切换验收（2026-09-17）

## 交付范围

客户端 0.3.1，基于现有多房间功能分支开发。本次不修改服务端代码、协议、数据库或部署配置，不部署、不停止、不重启线上服务。实际连接地址仅写入私有发布包，不进入源码或文档。

- Ctrl+R 打开切换窗口，口令掩码、昵称带入；Tab 切换输入项，Enter 确认，Esc 取消。
- 相同口令和昵称不重连；有草稿二次确认，成功前保留草稿。
- 未确认消息等待结果；失败、结果未知及清理事件不会被静默忽略，不自动重发。
- 新连接完成历史同步后才替换原连接；重名、拒绝、连接失败和超时保留旧房间。
- 候选连接、旧连接迟到事件、旧房间异步剪贴板及不同窗口的口令剪贴板相互隔离。

## 自动验收结果

- Windows：go test ./... -count=1、go vet ./... 通过。
- Linux 隔离临时目录：go test -race ./... -count=1、go vet ./... 通过，未改动服务器仓库或服务。
- 模型测试覆盖取消、掩码、同房间无操作、草稿确认、消息等待、混合成功/失败结果、连接超时、关闭两个连接、候选及旧事件隔离、剪贴板输入项隔离。
- 真实本机 WebSocket 测试覆盖目标昵称占用后保留旧房间、取消保留草稿、更换昵称进入目标房间，以及只在新房间持久化消息。
- 24×10、40×18、80×24 切换窗口尺寸检查通过，口令未出现在渲染文本。
- 新 exe 在 Windows ConPTY 100×30、40×18 中完成中文登录、Shift+Enter 换行、多行粘贴、Ctrl+R 打开切换窗口、单独 Esc 取消、成功切换新房间、消息隔离、缩放和退出。未向线上聊天室写测试消息。

## 使用与构建

    powershell -ExecutionPolicy Bypass -File scripts/build-client.ps1

默认连接本机测试地址；私有交付包通过 -Server 参数配置既有多房间服务。客户端和源码输出使用 0.3.1 文件名，不覆盖 0.3.0 发布包。详见 README 的“客户端内切换房间”。

本次实现保持单个可见房间，不提供口令收藏、多标签或后台未读。原生 Esc 有短暂的转义序列识别等待；不同外层终端拦截快捷键时仍需用户本机验收。
